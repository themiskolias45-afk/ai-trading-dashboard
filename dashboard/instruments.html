What would change this answer

Every number here is a paper trade — the same standing caveat as the rejection ledger: a screening signal for what to investigate, never realised P&L.

  • This is the D1 screen, not the walk-forward. The edgeisgold claim ran generateSignalMTF at gate 70; this ran the single-timeframe daily replay. Trade counts here run well above live firing rates and the trade set is not the one the live engine would take. It does not yet clear the bar that claim set for wiring an instrument in.
  • NAS100's live spread is still unmeasured. Every weekend reading is a stale last-quote, not a cost. tasks/spread_probe.py samples the session on both boxes; SP500 already reads 45 against a maxSpreadPts cap of 50, so a wide NAS100 could trip the gate and settle this regardless of the table above.
  • Candidates were replayed on Yahoo bars, not broker bars. The owned instruments used real MT5 history. A CFD's prices differ from the underlying — the gold futures/spot basis is the known example on this system.
  • Adding instruments does not fix the binding constraint. Sample size does. A second index trading roughly 15 times a year adds evidence slowly.
